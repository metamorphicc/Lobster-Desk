# Autonomous project exchange runner

This is executable exchange integration, separate from the paper web runtime. It is never started by `npm run agents` or FastAPI. The research/review service supplies hash-bound, unexpired BTC approvals; the runner independently sizes against a dedicated exchange account and submits through the real network-specific broker when explicitly armed. Default inspection does not create a transport or read a private key from a wallet provider.

Copy `.env.execution.example` to ignored `.env.execution` and supply the dedicated approved API wallet, its public account/agent addresses and explicit capital/absolute-loss/reserve limits. Never use the owner's main wallet private key. A nonzero account, API delegation, funds, compatible standard account scope and fresh market/account data are required. Keep a new network-specific execution journal separate from the paper database. Existing environment values take precedence over presets.

`npm run execution` inspects configuration without HTTP/dispatch. The owner can explicitly run `npm run execution -- --run --arm` after external acceptance; `--once` bounds it to one tick. These financial command forms were not executed during development. The launcher loads the same `.env.agents` public feed/application DB settings as the research service. Testnet requires `MARKET_SOURCE=hyperliquid-testnet`; mainnet requires `hyperliquid`. A live feed alone never arms this runner.

The runner holds an OS lease on its file-backed execution journal. It handles outstanding trades before considering new signals. It stages the strategy identity and holding-time limit atomically with the trade. Expired proposals, app pause, incompatible account modes, changed fee assumptions, capital-budget excess, reserve breach, stale/incomplete accounting and latched loss controls prevent entry. Each initial positive flat account establishes a durable observation baseline; cash deposits cannot erase losses or count as profit. Previously unknown history remains explicitly unknown.

Real partial fills receive actual-size exchange-native stops. Restart reconciliation never blindly replays an uncertain entry. Strategy time limits close only attributed exposure using reduce-only orders, and flat closure requires observed fills and cleanup. A normal time exit does not itself latch a loss halt. Accounting outages during recovery latch entry controls and still permit owned risk reduction; recovery is independent of model/provider availability. Unknown pre-entry leverage states can remain blocked for owner review instead of guessing that an order failed.

The web application still displays its independent paper account. Exchange journal balances/fills must not be confused with that simulated account. Receipt ingestion and public execution reporting are subsequent integrations, not automatically provided by a successful paper review.

Tests exercise the real broker/runner against an in-memory exchange, with no external financial writes. They cover signal-to-partial-fill protection, restart without duplicate entry, capital/fee refusal before any command, accounting outage exits and time-limit closure. Actual mainnet/testnet acceptance remains unobserved.
